# 固定预算 mixed Q128：顺序补充对照（2026-10-31）

本报告补充[原始 13 组正反序实验](benchmark-native-codec-fixed-budget-20261031.md)中的 `mixed-b1000000000-q128`。追加两次运行中，Native 的 trace 中位耗时为 **102.563/99.526 ms**，Raw 为 **117.238/115.598 ms**，分别少 12.5%/13.9%。原始反序中 Native 较 Raw 更慢的结果完整保留，未作为异常值剔除，也不与新数据合并成一个总体速度比。

## 配置与顺序

四个独立进程使用相同输入与代码文件。预算 1,000,000,000 B；48 层、BF16 KV、GQA 32:4、head dimension 128、原生页 128 tokens、Q=128、restore chunk=4。六个不可变会话的 context 为 `[128,1024,4096,128,1024,4096]`，同一条 32 请求串行 LRU trace；每个路径先暖机一条 trace，再记录三条。每条计时 trace 从空的逻辑 LRU 开始。

输入仍是历史 Qwen3-30B-A3B/OpenHands CPU BF16 捕获，校准位置 0:8、评估池 8:32，经旋转/重复构造会话；不是新的完整模型或 serving 测试。运行设备相同：H800 PCIe，UUID `GPU-fb9880e5-6155-b080-837a-948d5fd08b4c`；PyTorch 2.13.0+cu129、vLLM 0.30.0+cu129。

| 进程 | 第 1 位 | 第 2 位 | 第 3 位 | 第 4 位 |
|---|---|---|---|---|
| F | Raw | Native | Gather | Fused |
| R | Fused | Gather | Native | Raw |
| C1 | Native | Raw | Fused | Gather |
| C2 | Gather | Fused | Raw | Native |

F/R 是原始正反序，C1/C2 是看到波动后追加的确认。四行构成位置平衡的 Latin-square 式排列：每个路径在第 1–4 位各出现一次。它没有平衡所有相邻路径组合，也不是对时变主机环境的控制实验。三条 trace 是同一进程内的重复，不作置信区间或显著性推断。

## 稳定项与可定位的波动

审计了 48 条 trace、1,536 条请求记录。各路径在四个进程中的容量、逐请求命中/驱逐/目标 slot、传输字节和 chunk 数完全一致。

原始反序的变化同时落在策略＋恢复、元数据＋读取区间；命中请求不载入 KV payload，其读取区间也出现变慢。因此，命中率或传输字节变化不能解释这次差异。记录中的读取区间仍包含元数据 H2D、host 提交、48 层 GPU 读取与完成等待；没有独立 GPU 分段事件，不能把变化归因于 FA3、解码、PCIe 或 CPU 调度。

[逐 trace CSV](data/benchmark-native-codec-budget-controls-20261031.csv) 保留全部 48 行的原始 μs 时间、两个墙钟区间之和、循环余量、命中/字节/容量、实际峰值及来源哈希。原始 JSON 继续保留每条请求明细。

## 正确性与版本

四个进程均完成：独立验证 trace 对每次恢复先 poison，再核对全部 48 层 KV bits；Raw/Native/Gather 的 attention 输出与源数据 FA3 逐位一致。Fused 按原定 `atol=rtol=0.02` 通过，最大绝对误差 0.03125，并非输出逐位相同。所有计时 trace 的 GPU tensor 峰值均在 1 GB 预算内。
