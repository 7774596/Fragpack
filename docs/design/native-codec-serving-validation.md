# NativeCodec 的模型服务接入与压缩对照

本轮主线是独立无损 codec 的压缩比例、实际传输量、编解码开销和请求总耗时。
缓存仅增加编码前存在性检查以减少重复工作；不新增淘汰算法、预测预取或 NVMe 后端。
本文是执行协议，实际通过范围及数值另记于带日期的验证报告。

## 实现边界

- 固定官方 vLLM 0.30.0、LMCache 0.5.6、TP=1、eager、BF16 KV、full attention。
  attention backend 和模型 KV 写入保持原生，不改第三方源码，不包装 runner。
- 自有 KV connector 连接 scheduler 的前缀查找、页分配、请求结束和传输完成接口。
  首版固定请求结束时保存完整 prompt 块，未满尾块继续本地计算；Raw 与压缩使用相同时机。
- 自有 NativeBlockTransfer 直接读取原生页，输出 FPKB；恢复直接解码到独占原生页。
  GPU core 不依赖缓存服务、淘汰策略或 RPC。
- Raw 控制通过 raw gather/scatter、独立 FPNR 格式和相同 RPC 路径传递原始 BF16 数据，
  不进行熵编码。它是同接口对照，不代表原版 LMCache 最优原生传输实现。
- CPU L1 使用原版 LMCache 容量管理和 LRU。恢复不删除外部副本；保存前的
  `probe_many` 只返回瞬时存在性。外部淘汰后可重新保存，不能将 receipt 当永久驻留保证。
- GPU 与 pinned 池、候选、在途请求均有上限。source_ready 与发布 completion 分开；
  请求取消不取消已提交 CUDA 工作，所有资源等待最后一次使用结束。
- 当前 RPC 字节拷贝、变长元数据观察和后台完成等待计入性能；不将它们隐藏在初始化中。

## 验证顺序

1. CPU：身份隔离、跨缺口逐对象探测、池拒绝、失败/取消、页生命周期和完成通知。
2. GPU：原生非连续页 Raw/压缩往返，完整层 K/V 逐位比较，重复保存与源/目标所有权。
3. 小模型功能：真实原生 attention、外部命中跳过前缀、未满尾块、修改前缀、取消和重复请求。
4. 主模型：Qwen3-30B-A3B-Instruct-2507-FP8 权重、BF16 KV，沿用历史捕获校准的码表，
   报告其迁移来源和实际 fallback；重新核对选定 GPU 上模型加载后的可用 KV 预算。
   固定实际 GPU/CPU 预算，包含首次 prefill、编码、D2H、外部写入、重复恢复和生成。

## 对照及计时

主要比较 Raw 与 NativeCodec，使用相同请求 trace、保存时机、外部 LRU、进程顺序控制、
warmup 规则和停止条件。编码前探测的消融仅在捕获的不可变 KV 往返中运行，
不混入真实模型对照；相同 token 的独立重算可能产生不同数值，不能将它们当作同一份字节。
既观察能在 GPU 保留的热请求，也观察超过 GPU 容量、在外部预算附近反复访问的历史工作集。
接口接通与 GPU 逐位往返为功能结果；小模型 smoke 不代替主模型性能。

记录源版本和修改文件哈希、模型/码表身份、设备 UUID、依赖版本、独占检查、完整配置与失败。
统计总墙钟、请求 TTFT/TPOT/延迟、实际缓存 token、encode/restore 块数、D2H/H2D/RPC 字节、
外部存在跳过数、重新保存、任务等待、GPU/pinned 池占用和 L1 实际预算。
显式 JIT/模型初始化单列，首次冷请求、请求内额外触发的 JIT 和保存成本保留在 trace 中。
若使用离线模型引擎，
明确其不含 HTTP 前端；若使用 HTTP 服务，保留流式事件与服务端完成证据。

有限 L1 的容量和命中结果必须通过实际存储读取取得，不能由压缩比例推算命中率。
不为使压缩获益而给 Raw 移除原有去重；Raw 与压缩都使用相同轻量优化。
所有辅助 GPU 分配计入模型剩余预算，对工作区不同导致的原生页数量差异明确报告。
