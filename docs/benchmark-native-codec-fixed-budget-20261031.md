# 固定 GPU 预算：独立 codec 与 HBM 压缩的恢复/读取回放

2026-10-31 完成 **13 组正反顺序对照、26 个独立进程**。固定工作区后的独立
codec 与 raw 在所有可配对配置中具有相同的驻留 blocks 和命中序列，实际 H2D
payload 减少 **29.516%–29.517%**。七个 Q=1 主场景的整条 trace 时间下降
**10.71%–14.53%**；Q=128 的混合长度场景出现明显时段波动，不能概括为稳定加速。
HBM 常驻压缩的额外收益来自部分工作集能够完整驻留；当前融合 prefill 在 Q=128
下仍可能比 gather＋FA3 慢很多。

本轮测量的是**预先保存 KV 的恢复＋48 层只读 attention**。编码、归档构建、校准、
独立参考输出和正确性检查不计入时间；没有完整模型前向、生成或服务调度。
[完整 CSV](data/native-codec-fixed-budget-20261031.csv) 保存全部 **98 个 arm/进程
记录**，其中 94 个通过恢复和读取校验，4 个记录为预算内不可行；没有用 0 填补耗时。

同一 case 的四条路径执行相同的不可变会话 trace 和整会话 LRU，一次只有一个请求。
Raw/native 恢复到原生 BF16 页并调用 FA3；gather/fused 将压缩数据导入 HBM arena，
分别 gather 后调用 FA3、或直接融合读取。主实验 K=4、native 使用 decode 工作区；
压缩接收区始终按含 raw fallback 的格式上界预留。每 chunk 包含真实 pinned H2D、
状态 D2H 和完成等待，全部计入 host wall time。完整主机历史对四条路径均可用。

均匀 Q=1 场景先做**实际分配、冷恢复/读取及下一 block 越界探测**，再选择比原生页
整会话容量多一个会话的工作集；Q=128 沿用相同 trace，混合场景按 41-block 会话组
跨过该容量边界。这是容量边界实验，不代表线上自然命中率。每条 trace
包含首次访问、立即复用、两轮工作集扫描和首尾会话的连续访问；“burst”仅表示访问
集中，不表示并发到达。每进程预热 1 条、测量 3 条 trace，每条开始时清空逻辑 LRU。
第二进程反转 arm 顺序；两个进程的数据保留分层，不作为六次独立服务实验。

独立 codec 的字节收益与 HBM 的容量收益可以分开观察。例如 C=1024、0.5 GB、
Q=1 时，Raw/Native 都只能保留 35 blocks、发生 16 次 miss，传输量分别为
1,610,612,736 / 1,135,222,784 bytes。HBM 两个 reader 可保留 47 blocks，容纳
全部 5 个会话，miss 降到 5、传输量降到 354,758,656 bytes；这一额外下降来自
少恢复了会话。相反，C=4096、0.5 GB、Q=1 时，35 与 46/47 blocks 都不足以容纳
两个各占 32 blocks 的会话，所以四条路径仍各有 10 次 miss。

更高命中率也不能保证当前融合 reader 更快。C=1024、1 GB、Q=128 时，Gather
与 Fused 都只有 10 次 miss，但整条 trace 分别为约 78 ms 与 154–156 ms，后者
甚至慢于发生 31 次 miss 的 Raw/Native。该结果支持继续将原生 FA3 与当前融合
prefill 分开评估，不能把 Q=1 的收益外推到较长 query。

混合 Q=128 的**原始两次结果完整保留**：正向 Raw/Native 为
108.538 / 96.087 ms，Native 快 11.47%；反向为 129.382 / 173.181 ms，Native
慢 33.85%。反向三个 Native trace 为 175.581 / 173.181 / 163.633 ms，Raw 为
155.166 / 129.382 / 110.309 ms。restore 和 read wall 都变长，现有记录不足以确定
原因；不能删除这组结果或把不同进程最小值拼成收益。

K=1 的恢复 chunk 数由 K=4 的 32 增至 128，没有增加可完整驻留的原生会话数。
其正向 Raw 达 109.271 ms、反向为 57.241 ms，也存在时段波动；不能将正向
37.25% 的 Native 相对收益解释为稳定的恢复加速。K=16 减少完成等待，但更大的
接收区使 HBM 容量不足以保留全部工作集，miss 从 5 增至 16。all→decode 则在
同 K 下释放未使用的编码工作区，将 Native 容量从 27 增至 35 blocks；本 trace
的 miss 不变，没有据此观察到额外的稳定速度收益。

**预算边界需要保留回放本身的开销。** 本轮 0.5/1/2 GB 分别是
500,000,000 / 1,000,000,000 / 2,000,000,000 bytes 的 Torch GPU 张量峰值上限，
涵盖 KV、codec、接收区、metadata、attention scratch、Q/output 和 Graph 张量。
CSV 将 KV/codec/receive 与 Q/output、Graph 增量分别列出，reserved 另列。
这里的 Q/output 是回放为全部 48 层同时保留的测试张量；Q=128 时两者各占
50,331,648 bytes，真实 serving 通常不会同时保留全部层的 Q/output。

因此，C=4096、Q=128、0.5 GB 的“不可行”仅指**这个回放配置**：Raw 最小探测
峰值为 568,467,456 bytes，其中原生 KV 为 402,653,184、接收区为 50,331,648、
Q/output 合计 100,663,296 bytes，其余包括 FA3 临时量和元数据；Native 为
568,505,344 bytes。这不能推断真实模型或服务无法运行。模型权重、CUDA context/
驱动分配不在本测量中，也未测整进程物理显存峰值。该输入 raw fallback 为 0，
HBM overflow 按其实际需求配置；接收区的格式上界不代表 HBM overflow 的任意输入上界。

所有 26 个进程正常完成。对 94 个可行 arm，独立 validation trace 每次恢复前
破坏目标内容、检查全部 48 层 KV 位模式，并核对每个 attention 输出；Raw/Native/
Gather 输出逐位一致，Fused 最大绝对误差为 0.03125，通过 `atol=rtol=0.02`。
另逐请求审计 LRU、miss、eviction、payload/metadata H2D、status D2H 和 chunk 数，
与归档大小及 trace 完全一致；所有实际计时峰值均不超预算，释放后 allocated=0。
4 个不可行 arm 没有计时 trace，CSV 保留最小分配探测和原因。
