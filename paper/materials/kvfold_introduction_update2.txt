I. Introduction

Key/value (KV) caching avoids repeated computation by reusing attention states during generation and across requests with shared prefixes. This reuse is particularly useful for LLM agents, whose successive calls often share long contexts. Retaining these states, however, requires substantial memory. For Qwen3-30B-A3B, each token requires 96 KiB of BF16 KV across all layers, or 48 KiB per rank with a tensor-parallel (TP) degree of two. GPU capacity therefore limits active contexts, while external cache capacity limits how much history can be retained for later reuse.

To make better use of this capacity, vLLM's PagedAttention [1] organizes KV into fixed-size blocks allocated on demand in noncontiguous GPU memory. This reduces fragmentation and allows requests with common prefixes to share physical blocks. LMCache [2] extends reuse beyond GPU memory by storing KV in host memory or storage and retrieving it for later requests. Although these mechanisms improve utilization and retention, they leave the number of bytes per KV value unchanged. Reducing this remaining cost requires a more compact KV representation. KIVI [3], for example, quantizes keys per channel and values per token, using two-bit representations suited to their different distributions. For context transfer, CacheGen [4] quantizes differences between nearby tokens and then applies arithmetic coding to reduce the data sent when loading a context. Both approaches save space by approximating KV values. CacheGen's lossless coding preserves the quantized representation, so it does not recover the original BF16 bits.

Lossless compression can reduce storage while preserving these bits by exploiting redundancy in the underlying representation. nvCOMP [5] provides general-purpose GPU codecs, while SplitZip [6] separates BF16 exponents from the remaining bits and encodes frequent exponents compactly for transfer between prefill and decode workers. Using these representations in a paged cache also requires efficient restoration and allocation. If decoding produces a contiguous buffer, the recovered values must be scattered into their assigned KV pages, adding data movement and temporary storage. External allocators must also account for encoded record lengths so that smaller records allow more history to be retained.

To address these integration requirements, we present KVFold, a lossless KV-cache compression system for LLM agents. KVFold combines a compact BF16 representation with paged restoration and compressed GPU execution, and allocates external storage according to encoded sizes. The system supports two integration paths to accommodate different GPU cache layouts. In pool mode, completed KV blocks remain compressed on the GPU and are reconstructed as needed for attention. For deployments that retain the native GPU cache layout and attention implementation, tier mode applies compression in LMCache. Both modes use lossless high-byte coding and offline calibration, with record layouts tailored to their access patterns.
